# 架构与技术说明

## 一、总原则

> **Minecraft 拥有玩家；《深海迷航》拥有世界，并画出每一个像素。**

两边都是**真游戏**，各自跑自己的模拟，中间只做**翻译**，谁都不重新实现对方的机制：

| | 归属 |
|---|---|
| 玩家 | **Minecraft**：物理、碰撞、背包、血量/饥饿、方块放置与破坏、MC 怪物、相机（FOV/视角晃动/手部/第三人称） |
| 世界 | **《深海迷航》**：地形、生物与其 AI、光照、雾与水下焦散、音效、载具、基地、存档、剧情 |
| 氧气 | 默认深海迷航权威（映射到 MC 的空气条，MC 不会把你淹死） |
| 时间 | 深海迷航的昼夜驱动 MC 的时间 |
| 伤害 | 深海迷航 → MC **÷5**，MC → 深海迷航 **×5**（可配置） |

**《深海迷航》的地形永不被修改。** 海底只被"镜像"成 Minecraft 侧的隐形方块
（`subcraft:terrain`，不可破坏、无掉落），好让 MC 侧的物理、寻路、流体、爆炸等逻辑正常推理。

## 二、两边的组成

```
《深海迷航》侧（BepInEx 5 插件，C# / net472）        Minecraft 侧（NeoForge 1.21.1 mod，Java 21）
  Link/     共享内存协议、输入环、命令盒                 link/     同协议的 Java 镜像
  Player/   傀儡（接管玩家）、输入路由、相机、隐藏潜水员    world/    幽灵地形、干燥体积、三角碰撞
  World/    地形碰撞采集、八叉树探针、救生舱锚定           capture/  抓 MC 的顶点/贴图（世界段、手部）
  Render/   把 MC 的几何送进 Unity（材质、点光、网格）      client/   输入注入、相机、声音、HUD 叠加
  Combat/   生物代理与受击                                combat/   深海迷航生物作为 MC 实体代理
  Audio/    MC 音效走深海迷航的 FMOD（含水下闷响）          items/    物品桥的 MC 侧（本仓库新增）
```

## 三、数据通道（一块共享内存 `link.bin`）

| 区域 | 方向 | 用途 |
|---|---|---|
| `HostState` | 深海迷航 → MC | 玩家位姿、瞄准、视口、时间、氧气、标志位 |
| `McState` | MC → 深海迷航 | MC 玩家位姿/速度、相机、血量/饥饿/空气、帧号 |
| 输入环 | 深海迷航 → MC | 键盘/鼠标（GLFW 码），屏幕打开时另有光标坐标与文字 |
| **命令盒** | 深海迷航 → MC | 把 `/give …`、`/setworldspawn …` 这类命令交给 MC 执行（本仓库的物品桥与出生点锚定就走这里） |
| 碰撞环 | 深海迷航 → MC | 地表三角面 + 区块体素（幽灵地形） |
| 渲染环 | MC → 深海迷航 | 被抓取的几何：静态区块段、每帧动态批次、手部 |
| 叠加层 | MC → 深海迷航 | MC 的 GUI/HUD 像素（三缓冲） |

协议以 `protocol/subcraft_protocol.h` 为唯一真源，两侧各有镜像并用 `layout.json` 做布局测试；
本仓库**没有改动协议版本**（仍是 v25）。

## 四、本仓库相对上游的改动

见 `patches/host.patch`、`patches/guest.patch`（基线提交见 `patches/UPSTREAM_COMMIT.txt`）：

| # | 改动 | 为什么 |
|---|---|---|
| 1 | guest：开发世界用 `GameType.CREATIVE` 创建 | 上游代码是 SURVIVAL，但文档写"创造"，导致 E 打开生存背包、拿不出方块 |
| 2 | guest：dev 客户端内存 2G → 6G | 上游按 8GB Mac 调的；本机实测堆顶到 1900/2048MB、帧率掉到 55 |
| 3 | host：`F11` 不再转发给 MC，改为**切换深海迷航自己的全屏** | 上游把 F1..F15 全转发，F11 会触发 MC 全屏，把隐藏的 MC 窗口顶到最前 |
| 4 | guest：MC 窗口改为**每帧重申隐藏** | 上游只隐藏一次，任何让它重新可见的路径都会把原版窗口留在最前 |
| 5 | **物品桥（新）**：`Items/ItemBridge.cs` + guest `items/SubItems.java`、`SubnauticaItem.java` | 深海迷航拾取物 → MC 背包（单向，v1 是复制）；用一个物品 + `minecraft:custom_data` 承载 TechType 与中文名 |
| 6 | **出生点锚定（新）**：`World/WorldAnchor.cs` | 读深海迷航自己的出生点 → `/setworldspawn` + `/spawnpoint`，复活不再掉虚空 |
| 7 | guest：取消失空死亡并把玩家拉回水面；host 在菜单/加载时把玩家待在水面 | 出生点修复前的死亡循环兜底 |
| 8 | **命令队列（新）**：`Link/GuestCommands.cs` | 命令盒只有一个槽位，多个 host 系统要发命令，统一排队逐帧推送（上游 host 从不写这个盒） |
| 9 | guest：`holdUntilReady` 增加"宿主说这里没地面"与"与区块无关的 4 秒墙钟上限" | 边缘/虚空里旧的等待逻辑会把玩家永久钉住（"卡住不动"） |

## 五、怎么调试（开发用）

```powershell
# 深海迷航侧：读日志
Get-Content '<游戏目录>\BepInEx\LogOutput.log' -Tail 50
# 游戏内自检（需要先设 DevSlot 到一个专用档）
python tools\sn_cmd.py --scenario tools\scenarios\load_dev_slot.jsonl
python tools\smoke.py            # 12 项联动自检

# Minecraft 侧：跑一条命令、看场景统计
python tools\mc_cmd.py "subcraft dump"
python tools\mc_cmd.py "/gamemode creative"
```

**日志里最有用的几行**：`SubCraft diag: linked … puppet … inGame …`（链路与接管状态）、
`SubCraft items:`（物品桥推了什么）、`released player at …`（玩家何时被解除钉住）、
`Minecraft's player is inside terrain …; lifting…`（host 抬升玩家——已知粗糙点）。

## 六、已确认的性能现实（后续要治）

- 世界是 **flat 生成器 + 单层 water 高度 2032**：每区块 **52 万方块**，视距 6 时约 8800 万方块
  → MC 堆内存轻易到 5~6 GB，飞行时生成新区块是帧率尖峰的主因。计划改成"整段 O(1) 填充"的自定义生成器。
- 深海迷航**自身**的地形碰撞只有相机周围 **5×5×5 个 16 格单元**的窗口；窗口外没有地面。
  上游用"未知=实心"兜底，这就是玩家感觉到的"空气墙"。计划改成用**八叉树**（流送范围远大于碰撞）
  按列下发"地面高度+材质"，由 MC 侧铺方块，然后删掉所有兜底。
